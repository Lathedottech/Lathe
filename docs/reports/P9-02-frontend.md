## 3. Technical decisions

- **The browser talks only to the Workspace origin.** `next.config.ts` proxies `/auth/*` and `/v1/*` to `LATHE_ENGINE_URL`, so the Better Auth cookie lives on the Workspace origin. Rejected alternative: the browser calls the Engine directly. That would need CORS with credentials and a cross-site cookie.
- **Server Components forward only the incoming `cookie` header.** They send `cache: 'no-store'` and `redirect: 'manual'`, with a 5 s timeout. Rejected alternative: forwarding all headers, which could pass client-chosen headers to the Engine. No org id is ever sent. The org changes only through `POST /v1/session/active-org` with a membership id.
- **Deny by default on `GET /v1/me`.** A 401 redirects to `/sign-in`. Any other failure renders an error and **no shell**: Engine down, 5xx, a 3xx, a body that fails the strict C4 `Me` schema, or a missing or invalid `LATHE_ENGINE_URL`. Rejected alternative: redirecting on every failure, which hides real errors and loops when the Engine is down.
- **`SectionGuard` on every page** re-reads the session (deduplicated per request with React `cache`), because App Router layouts do not re-run on client navigation. It shows "Choose an organization" when no org is active, and "You don't have access" when the role lacks the section's permission. Each section maps to a C4 route permission. A unit test checks that each mapped permission is declared in `ROUTES`. This is a UI hint only: data pages call the Engine, which authorizes every request (the e2e checks a direct `GET /v1/projects` returns 403).
- **No default Engine address.** Without `LATHE_ENGINE_URL` there is no proxy and no call. Rejected alternative: a `localhost` default, which would silently reach whatever listens there.
- **Real data where C4 has a route:** Projects (`listProjects`), a project (`getProject`), Agents (`listAgents`), and Settings (`Me`). Overview, Specifications, Factory Runs, Verification and Deliveries show an empty state that says where the data lives. Overview has no data because P9-03 is cut from the demo scope (plan of Nov 27). No sample numbers anywhere.
- **The project selector** lists real projects and opens `/projects/:id`. It stores nothing. It is hidden when the role cannot read projects.
- **The fake Engine fixture** (`e2e/fake-engine.mjs`) implements only the routes the shell uses, with C4 status codes and the `{code, message, requestId}` error shape. It checks `Origin` on POST like Better Auth, and returns 404 for a project or membership of another org or user. The Workspace validates its responses with the same schemas as a real Engine's. It adds one role, `limited`, which the real Engine does not have, to test "role without permission". All real Engine roles grant every read.
- **webpack build:** `shared-contracts` imports `./x.js` for `./x.ts`. Turbopack does not map that, so the build uses `--webpack` plus `extensionAlias`, the same as `apps/support-desk`.
- **UI reference handoff:** used the P9-02 nav exactly and the "role in the org" instead of a plan name. No invented counts, no "Agents online". The glass and glow look is not applied yet; only P9-00 tokens and components are used.

## 6. Remaining issues

- **The run against the real Engine has not happened.** The fake fixture stands in for it. Until P3-04 is runnable, the acceptance item "Playwright against the real Engine" is open.
- The Engine's Better Auth `trustedOrigins` must include the Workspace origin. Otherwise sign-in through the proxy fails the origin check. This is for A in the Engine composition root.
- The real Engine's cookie may be `__Secure-lathe.session_token` (`useSecureCookies: true`). That is fine over https. On plain `http://` to a non-localhost host, the browser drops it. The fixture uses a plain cookie name.
- Sign-in sends users to `/projects`, not Overview, because Overview has no data in this scope.
- There is no mobile hamburger menu. Under 64 rem the sidebar becomes a horizontally scrollable row. P9-07 covers responsive polish.
- A user who cannot read projects still sees the "Go to Projects" link in an empty state. It leads to "You don't have access" and shows no data.
