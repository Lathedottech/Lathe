## 3. Technical decisions

| Decision | Rejected alternative | Reason |
|---|---|---|
| Security rules as Zod literals and refinements (sandbox hardening flags, `mcpServers` must be empty, foundation mount read-only, no credential in a verifier, fault injection only on demo runs) | Rules only in prose and in implementations | A spec that relaxes a rule fails to parse, so implementations cannot drift silently |
| Mount sources are an enum (`target-app`, `application-foundation`, `kiro-runtime-config`) | Free host paths | The harness and `.github/` cannot be expressed, so they cannot be mounted |
| `VerificationReport` derives `overall` from the gates and enforces fail-fast order | Trust the reported `overall` | A report cannot claim a pass that its gates do not show |
| `resultHash` preimage defined in C3 as text; the harness computes it | A hash function in the contract | Contracts hold no runtime logic |
| Request bodies are strict objects without `orgId`, role or verdict fields | Lenient objects | The org comes from the membership; unknown keys are rejected |
| `ROUTES` table with a permission per route and no merge or deploy route | Routes defined only in the Engine | Deny-by-default can be checked against one list; the Workspace gets typed endpoints |
| Run states follow TASKLIST P3-02 (no separate TESTING state) | The older list in ARCHITECTURE.md §3 | TASKLIST is the source of truth for tasks |
| `zod` 4.6.7, pinned exactly, the only dependency | Another validator | Already chosen in the stack; latest release on 2026-11-17 |
| C1 `fixtures` has two strategies (`via-actions`, `seed-script`) | Decide now | Needs B's P1-05/P1-06 findings; left open in the file header |
