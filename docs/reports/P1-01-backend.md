## 3. Technical decisions

- **Drizzle schema plus a hand-written SQL migration.** Rejected: `drizzle-kit generate`. Generated SQL cannot express the `REVOKE` on the audit table, and the security rules want migrations reviewable as plain SQL. A test compares the Drizzle definition with `information_schema`, so the two cannot drift silently.
- **Append-only audit enforced by privileges.** `REVOKE UPDATE, DELETE` from the app role. Rejected: a trigger that raises on update. A trigger can be dropped by anyone with ownership; a missing grant is the simpler and stronger control and is what `security.md` asks for.
- **`audit_events.org_id` and `actor_id` are nullable.** Denied requests before membership resolution (unauthenticated, unknown org) still need an audit row. Rejected: `NOT NULL`, which would drop exactly the events we most need.
- **`outcome` limited by a `CHECK` to `allowed`, `denied`, `success`, `failure`.** Rejected: free text. P1-05 may narrow this.
- **`memberships.user_id` has no foreign key yet.** The users table comes from the auth library in P1-03. Rejected: creating our own users table now, which would conflict with Better Auth (D10).
- **No `pgcrypto` extension.** `gen_random_uuid()` is built into PostgreSQL 13 and later. The owner role is non-superuser, so the migration should not depend on creating extensions.
- **Integration tests are a separate command (`pnpm test:integration`).** Rejected: putting them in `pnpm test`, which would break the unit run for anyone without Docker. The helper throws when variables are missing, so the integration run fails loudly instead of skipping.
- **Dependencies, pinned exactly:** `drizzle-orm 0.44.7` (schema, D7), `pg 8.23.1` (Postgres driver for tests and later `withTenant`), dev: `@types/pg 8.23.1`, `@types/node 22.20.5` (matches the Node 22 target), `vitest 5.1.0` (same version as root, needed to resolve `vitest/config` from the package).

- **Auth tables** ("auth tables from the library" in the task) are deferred to P1-03 with Better Auth; `memberships.user_id` gets its foreign key then.
- **Not run on Node 22.** Local Node is v24.14.0.
- The local port is 5433, not the default 5432, because another project's container (`sparkkit-postgres-1`) uses 5432 on this machine. It is only a local `.env` value.
